Internal build — carries the `-dev` suffix; the update channel it belongs to is
`dev`.

**Fixes the boot crash in 0.1.3-dev.** That build could not start the app at all
on a real install: the window appeared, the harness died a moment later, and the
app showed *The DSH harness failed to start* (`ERR_CONNECTION_REFUSED`). The
cause was a runtime flag. Launched from Finder there is no `node` on `PATH`, so
the shell runs the harness through Electron-as-node — and on that path the
harness's live-reload service refuses to start without `--expose-internals`,
which takes the whole harness down with it. Launched from a terminal the shell
finds `node` instead, which is why the problem never showed up here. The flag is
now passed whenever the harness runs as Electron-as-node.

There is a test for exactly this now: `pnpm smoke:finder` runs the app the way a
double-click does — no `node` on `PATH` — so the path a real install takes is
the path we check. The previous smoke could not see it.

**The loading screen is type, not a picture.** It shows `starting mitsumeru` and
the line, set in JetBrains Mono, with the app mark removed — the icon already
says whose app this is, in the Dock and in the installer, and repeating it
full-size read as a second logo rather than as a loading state.

**Brings the DeepSeek 4.1 model adapter.** Wraps DeepSeek Harness 0.1.5-rc.1,
which adds `DeepSeek-V41-Flash` (`deepseek-flash`) — text and image input, and
system-prompt updates within a conversation's history. New conversations default
to it. This is the reason to move off 0.1.5-alpha.2: that release has no V4.1
adapter at all.

rc.1 rather than rc.2 by the repository's own 24-hour release-age gate: rc.2 is
the same 0.1.5 line with the V4.1 adapter byte-for-byte unchanged, and it is only
hours old, so it is excluded until the gate clears it. Nothing in rc.2 is
missing here.

Signed with Developer ID, notarized by Apple, stapled. Gate: `pnpm verify:release`,
plus the packaged-app smokes (smoke, smoke:finder, smoke:native, smoke:updater).
